## Correções da revisão
- `dominio_sus.codigo_oficial` = ID (texto) em 7 listas do SIH/SIA (FHLEITOUTITP, FHCLASSIFDIAG, FHJUSTPACDESC e os
  4 FAHEMO*): o id é o código do Ministério (evidência: carga dos domínios dos leiautes no new-sgh). FGTBTPCREDOR fica
  sem código oficial, com motivo (sem evidência; o cliente completa).
- CMTPCONTRATO = esfera confirmada pelo contrato da contratualização do new-sgh (3 códigos: federal, estadual,
  municipal); evidência no motivo.
- Conferência por agregado na imagem de referência não foi possível (acesso ao Firebird negado nesta sessão).

## Defeito do modelo encontrado (pedidos 1 a 3 em saida/L8-07.json)
`dominio_sus.lista` é VARCHAR(30), mas o próprio CHECK e a API usam `caracteristica_tratamento_dialitico` (35) e
`justificativa_paciente_sem_documento` (36). Decisão: alargar para VARCHAR(40), nunca encurtar a lista. Faltam três
mudanças fora dos arquivos da fatia (a criação da migração foi negada nesta sessão):
1. a migração nova `13_SUS/06_tabelas.sql`, com o texto pronto no pedido;
2. o `mapa.ler_ddl` levar ao DDL da conferência os ALTER só com MODIFY (impacto conferido: nenhuma outra fatia);
3. a conciliação ou a cobertura tratar como falha a tabela carregada com 0 gravados.
Até lá, FAHEMOCARTRAT e FHJUSTPACDESC gravam 0 (recusa `restricao_destino_1406`): **a fatia carrega 16 de 19, não 18**.
Ao aplicar, troque `LARGURA_LISTA` para 40 em `sintetica_d/l8_07.py`. Os testes já aceitam os dois estados, e o teste
da imagem só admite 0 gravados nas listas longas.

## Sentinela 'não informado' (id 0) da rede assistencial e do tipo de indicador
O id 0 entra INATIVO: `ativo` = ID pela regra `booleano` (0 -> falso). O produto representa 'não informado' com o
vínculo NULL, então o item nunca é escolhível. A decisão está em F4-decisoes-destino.md. A imagem sintética tem uma
linha de id 0 nas duas tabelas, e há teste do plano e da regra.
